Important behavior
------------------
- Checkout permits guests and uses Cash on Delivery; stock and prices are recalculated server-side inside a database transaction.
- Image cleanup is not run synchronously. Zero stock for two days only makes eligible non-primary product images cleanup candidates; candidates receive a seven-day grace period and are rechecked before object deletion.
- Configure `DJANGO_DEBUG=1` for local development. Production must set `DJANGO_SECRET_KEY`, PostgreSQL settings, allowed hosts, HTTPS settings, and a shared `REDIS_URL` for distributed rate limiting.

Local setup
-----------
1. Create and activate a virtual environment, then install `requirements.txt`.
2. Start the local PostgreSQL service, then create a PostgreSQL login role and database owned by that role.
3. Export `DJANGO_DEBUG=1` and the `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_HOST`, and `POSTGRES_PORT` values for the local database.
4. Run `python manage.py migrate`, then `python manage.py createsuperuser`.
5. Start the development server with `python manage.py runserver`.
6. For production also set `DJANGO_SECRET_KEY`, `DJANGO_ALLOWED_HOSTS`, `REDIS_URL`, TLS/HTTPS settings, and persistent object/media storage.

Local Kali startup troubleshooting (checked 2026-10-21)
------------------------------------------------------
- System Python has Django, Pillow, and psycopg installed.
- `DJANGO_DEBUG=1 python3 manage.py check` succeeds. Without that environment variable, settings correctly reject a missing production secret key.
- `runserver` cannot start until PostgreSQL is reachable: this machine has PostgreSQL 17 and 18 clusters installed, both stopped; the configured PostgreSQL port is 5432 (cluster 18).
- Start the local database with `sudo pg_ctlcluster 18 main start`. Create a local role/database with `sudo -u postgres psql`, then configure `POSTGRES_*` values to match. `sudo` requires the developer's password, so it cannot be run from this session.
- Then run `export DJANGO_DEBUG=1 POSTGRES_DB=mrcomputers POSTGRES_USER=mrcomputers POSTGRES_PASSWORD='<your-local-password>' POSTGRES_HOST=127.0.0.1 POSTGRES_PORT=5432`, followed by `python3 manage.py migrate` and `python3 manage.py runserver`.
- Do not use SQLite as a workaround; this application is configured for PostgreSQL.
